# MyDNS-Adapter

MyDNS.JP Adapter for Windows : IPアドレス通知ツール

このツールは、Windows環境で動作するコマンドラインツールおよびWindowsサービスです。
MyDNS.JPに対して定期的にIPアドレス通知します。

## 主な機能

*   **Windowsサービス実行**: 一度インストールすれば、バックグラウンドで自動的にIPアドレスを監視・通知します。
*   **マルチアカウント対応**: 複数のMyDNS.JPアカウントを登録し、一括で管理できます。
*   **IPv4/IPv6両対応**: IPv4とIPv6のIPアドレスをそれぞれ通知するかどうか、アカウントごとに設定できます。
*   **シンプルなCLI**: コマンドラインから対話的にアカウントの追加・編集・削除ができます。
*   **ログ機能**: サービスや通知の実行結果は、実行ファイルと同じディレクトリの `mydns.log` に記録されます。

## クイックスタート

### 1. 以下のどちらかを選んてください。

ほとんどの方は使うだけだと思いますので、1-Aでいいと思います。

### 1-A. EXEをサクッとダウンロード

Releaseから最新版のEXEをダウンロードしてください。ほとんどの人はこれで終わりです。

### 1-B. Rustのソースコードからビルド

Rustのツールチェインが必要です。以下のコマンドでリリースビルドを行います。ホントにするの？

```sh
cargo build --release
```

Windows 11 x64向けMSVCビルドは、リポジトリ直下の`.cargo/config.toml`でCランタイムを静的リンクします。リポジトリ直下からビルドし、配布前にVC++ランタイム未導入のWindowsでも起動することを確認してください。`RUSTFLAGS`などでこの設定を上書きした場合、別途ランタイムDLLが必要になる可能性があります。

### 2.適当なディレクトリにEXEをコピーします

ダウンロード(またはビルト)したEXEファイルを `C:\MyDNS-Adapter\` のような任意の永続的なディレクトリにコピーします。

## 実行権限

アカウントの追加・編集・削除・表示、および`--notify`・`--ipv4`・`--ipv6`による手動通知を含むCLI操作は、管理者として起動したPowerShellまたはコマンドプロンプトから実行してください。権限不足の場合は、設定が未登録であるかのように扱わず、管理者権限が必要である旨を表示します。Windowsサービスは`LocalSystem`アカウントで実行されます。

### 3.アカウントの追加

コマンドプロンプトやPowerShellを管理者権限で開いて、以下のように起動して、通知したいMyDNS.JPのアカウント情報を登録します。

```sh
# C:\MyDNS-Adapter\ にコピーした場合の例
# 対話モードでアカウントを追加
C:\MyDNS-Adapter\mydns-adapter-win11.exe --add
```

アカウントは複数登録できますし、後から変更や削除などもできます。
詳しくは下記のオプションコマンド一覧をご覧ください。

### 4.Windowsサービスとしてインストール

続いて、以下のようにコマンドを実行して、サービスとして登録します。

```sh
# C:\MyDNS-Adapter\ にコピーした場合の例
C:\MyDNS-Adapter\mydns-adapter-win11.exe --install
```

サービスは起動直後に通知を試み、その後は通知開始時刻を基準に5分周期で動作します。各周期の開始時に設定を読み直すため、アカウントの追加・編集・削除は次回周期に反映されます。設定が0件でもサービスは停止せず、次回周期に再確認します。1件のHTTP要求は最大15秒、一巡の通知処理は最大4分です。

同名サービスが別のEXEを参照する場合、`--install`・`--restart`・`--uninstall`は変更せずにエラーを返します。`sc.exe qc MyDNSAdapterService`で登録先を確認し、元のアプリケーションの管理手順に従ってください。サービス登録後はEXEを移動しないでください。

## コマンド一覧

| オプション             | 短縮形 | 説明                                                               |
| :--------------------- | :----- | :----------------------------------------------------------------- |
| `--add`                | `-a`   | 新しいアカウント設定を対話的に追加します。                         |
| `--edit [MASTER_ID]`   | `-e`   | 既存のアカウント設定を編集します。IDを省略すると対話的に選択します。 |
| `--remove <MASTER_ID>` | `-r`   | 指定されたMasterIDのアカウント設定を削除します。                   |
| `--view`               | `-v`   | 現在の設定を一覧表示します。                                       |
| `--list`               | `-l`   | `--view` と同じです。                                              |
| `--notify`             | `-n`   | 設定されているすべてのアカウントで、IPv4/IPv6アドレスを即時通知します。 |
| `--ipv4`               | `-4`   | IPv4アドレスのみを即時通知します。                                 |
| `--ipv6`               | `-6`   | IPv6アドレスのみを即時通知します。                                 |
| `--install`            |        | Windowsサービスとして登録、起動します。（要管理者権限）             |
| `--uninstall`          |        | Windowsサービスを停止し、解除します。（要管理者権限）               |
| `--restart`            |        | Windowsサービスを再起動します。（要管理者権限）                     |

## 設定の保存場所

このツールで登録したアカウント情報（MasterID、パスワードなど）は、Windowsレジストリに保存されます。新規保存・編集時のパスワードは、DPAPIのマシン単位保護で暗号化したREG_BINARYとして保存し、アカウントキーはSYSTEMとAdministratorsのみがアクセスできるACLにします。マシン単位DPAPIのblobは同じPC上でアクセスできるユーザーが復号できるため、レジストリACLも保護の一部です。暗号化前のREG_SZパスワードも後方互換のため読み取れますが、一括移行は行いません。アカウントを明示的に編集して保存すると、その設定のパスワードが暗号化されます。
*   パス: `HKEY_LOCAL_MACHINE\Software\MyDNSAdapter`

Windows 11 x64では32bit版・64bit版アプリが異なるレジストリビューを参照する場合があるため、本ツールは両ビューを確認します。新規設定は64bitビューに保存し、既存設定の編集・削除は設定が存在するビューで行います。両ビューに同じアカウントの異なる設定がある場合、そのアカウントの通知・変更・削除は自動で選択・移行せず、ログに競合を記録します。

新規追加で受け付けるMyDNS MasterIDは`mydns`に続く半角数字6桁の形式です（例: `mydns123456`）。既存設定は後方互換のため読込時にこの形式で再検証しません。明示的な削除は不正設定からの復旧にも使えますが、同じIDが両ビューに存在して競合する場合は削除先を自動選択しません。

不正なアカウントはログに理由を記録して除外し、正常なアカウントは継続します。設定が存在しても全件が不正・競合なら、未登録ではなく設定読込エラーとして扱います。サービスは読込・通信失敗後も次回周期を試みます。手動通知は全対象成功なら終了コード0、0件・読込失敗・一部または全件の通知失敗なら非0です。CLIのプロトコル指定と各アカウントの通知有効設定の両方を満たす要求だけを送ります。

ログはプロセス間Mutexで排他し、ローテーション時に最新10,000行を保持します。書込みごとの全件再作成を避けるため、次のローテーションまでは最大10,100行になります。行数管理の`mydns.log.state`はログと同じ場所に置かれます。LocalSystemが書き込める永続ディレクトリを使用し、一般ユーザーがEXEを置き換えられる場所へのサービス配置は避けてください。
